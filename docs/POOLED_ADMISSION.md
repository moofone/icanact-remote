# Pooled admission and forwarding migration

This migration retains the REMOTE-1..5 contract and does not establish whole-tree conformance. In particular, allocator/copy counters and same-host release comparisons still require host execution.

## Aligned receive owners

`AlignedBytesPool::new_with_budget(count, bytes)` now bounds the number of simultaneously checked-out owners and the aggregate capacity of idle plus checked-out buffers. Defaults are 64 owners and 64 MiB. Checkout growth reserves a power-of-two capacity class and checks actual capacity before exposing an owner. The maximum single checkout class is the configured aggregate byte budget; idle buffers larger than 8 MiB are released rather than retained.

`PooledAlignedBuffer::{with_len, with_len_uninit, from_slice}`, `AlignedBytes::from_pooled_slice`, and `AlignedBytesPool::get_buffer` now return `Result`. Exhaustion, excessive size, or competing byte reservation returns `GossipError::WriteQueueFull` before requesting allocation. Actual allocator capacity is checked before owner publication; physical allocator overhead/rounding peak is not measured. `get_buffer` requires an `Arc<AlignedBytesPool>` and returns an initialized RAII owner rather than a growable raw vector. The raw return API is private: dropping an owner returns its admission exactly once. Fallible framed readers propagate rejection; they must not skip a payload body and continue framing.

Unique aligned owners retain their original allocation directly. Creating shared slice views is explicit and retains the original owner, count admission, and full capacity charge until the last view drops. Borrowed storage is never forcibly recycled. Caller-held payload lifetime is therefore ownership-bound, not a timer that could invalidate borrowed bytes. Higher-level stream/read deadlines remain responsible for asynchronous receive lifetime.

## Typed byte payloads

`PooledPayload::try_from_pooled_bytes(length, fill)` returns `Result<PooledPayload>` rather than `Option`. `fill` receives `BoundedByteWriter`, supporting `extend_from_slice`, `push`, `resize`, and `Extend<u8>`. It cannot obtain a growable Vec. Writing beyond the declared length causes whole-encode rejection; partial payloads are never returned.

A process-wide 64 MiB live byte budget charges each owner its power-of-two capacity class, at least the 1 MiB reuse class, limiting active byte checkouts to 64. The maximum encoded byte payload is 8 MiB. The idle pool separately retains at most 64 MiB and 4096 entries. Payloads above the 1 MiB idle-retention class remain supported through bounded unpooled storage; this path is explicitly not an allocation-free-after-warmup claim. Exhaustion and contested reservation return `WriteQueueFull` before invoking `fill`.

The native `into_forward_payload` conversion moves the existing serializer or byte-pool owner directly, including advanced offsets, without allocating shared-owner metadata. Explicit compatibility conversion to `Bytes` preserves admission but may allocate owner metadata and is outside the required native hot path. `PooledPayload::from_owned(ForwardPayload)` also transfers an already-proven whole owner without copying; it adds no pool admission, so the downstream queue must reserve count and byte capacity before retaining it. `retained_bytes()` reports the actual retained capacity for downstream queues. Serializer checkouts are globally limited to 64 contexts, returned on serialization errors and unwinding. Each admitted context reserves a 4 MiB aligned archive writer, a 1 MiB scratch slab, and 4096 sharing slots (three usize fields each) before invoking serialization. Writer requests are checked before extending; scratch requests account for alignment and size before returning a disjoint pointer. Neither adapter grows its backing allocation. The distinct typed archive-body cap is 4 MiB; exceeding it or the 1 MiB scratch cap returns `WriteQueueFull`, with no partial payload. This class plus its type prefix fits the unchanged inline response-lane budget. Idle contexts retain these fixed reservations for reuse. On 64-bit hosts total writer/scratch/sharing backing capacity is at most 326 MiB across idle and checked-out contexts, plus fixed context and queue metadata. Downstream queues charge the complete owner (5 MiB plus 96 KiB sharing slots on 64-bit hosts) even for a tiny archive, which can reduce admitted concurrency. The convenience copying encoder also uses this bounded serialization path before making its documented output copy.

`WireEncode` now uses `BoundedSerializer<'a>` rather than the concrete growable writer/ArenaHandle/Share composition. Derived serializers continue to work; custom implementations must use the bounded writer/allocator and must not allocate or block independently. A sticky rejection receipt rejects the entire archive with `WriteQueueFull` even if custom code swallows an adapter error. Existing wire prefixes and shared-object identity remain unchanged.

Sharing uses a reusable fixed table with 2048 distinct-pointer admission and at most 16 probes per lookup. A full collision window also returns `WriteQueueFull`, even below the count limit; admitted aliases retain their original positions and cycles remain Pending under rkyv's existing semantics. Sticky saturation rejects the entire encode if a custom serializer ignores sharing failure. No temporary growable Share map is created.

When an offered writer slice already proves the 64 MiB wire hard limit is exceeded, the encoder preserves `MessageTooLarge` with the observed saturating position-plus-length lower bound, without constructing the archive. Ordinary 4 MiB archive-capacity exhaustion remains `WriteQueueFull`; this is not a second serialization or size-estimation pass.

VectorClock serialization separately admits at most 65,536 entries per outbound clock and 8 MiB of aggregate logical entry bytes being traversed. The stricter 4096-entry inbound limit is unchanged. Admission tries at most eight atomic reservations without waiting, returning a serialization error with a WouldBlock source on capacity or contention. One immutable map guard feeds both passes of `ArchivedVec::serialize_from_iter`; no intermediate Vec or copied map snapshot is collected. Each tuple is materialized on the stack and element resolvers use the bounded serializer allocator. The scalar resolver retains only the admitted length and `VecResolver`, so resolution neither reloads a changed clock nor retains the old map. Logical-entry admission ends after serialization, including failure and unwinding; completed payloads retain only their archive/scratch/sharing owners.

**Verification pending:** the direct-map change removes the identified intermediate snapshot in source, but does not establish whole-path zero allocation, copy or reference-count cost. Existing explicit compatibility conversion to `VectorClockData` still allocates by design. Authored controls compare legacy wire bytes, mutate a clock during serialization and before resolve, verify old-map release, and measure scoped warmed encoding with alias and allocating positive controls. These tests and whole-path allocator, concurrency, overload and release-performance measurements have not run. Arbitrary external `Serialize` code cannot be sandboxed.

## AskForwarder

Forwarding methods now accept `ForwardPayload` for the request and timeout/error fallback payloads. Construct it from a complete `Vec<u8>`, `Box<[u8]>`, pooled typed payload, or a static slice. `TryFrom<AlignedBytes>` preserves a known pooled or `from_aligned_vec` owner without copying and rejects opaque `from_bytes` owners. Aligned-vector slices retain the original full-capacity receipt. Arbitrary Bytes views cannot enter through an unchecked conversion because their retained backing allocation is not observable. `copy_from_slice` is an explicitly copying convenience constructor for callers that choose that behavior; forwarding admission never silently compacts an owner.

`ForwardPayload` is a unique inline owner enum, not implicitly `Clone`. Native Vec, boxed, static, aligned and pooled owners move through writer admission. `as_bytes()` borrows a slice; `into_bytes()` is an explicit compatibility promotion that can allocate metadata. Aliasing requires explicit `into_shared`/`shared_clone` and charges the complete retained allocation. Native timed, no-timeout and deferred actor-ask methods retain this owner through routed framing. `DeferredAsk<'session>` now borrows the submitting connection session's tracker. Handles can be awaited concurrently within that scope, and cannot outlive or replace the exact session. Spawned tasks must own their session before submitting; no request acquires a tracker `Arc`. Submission deadlines and exact-ID cancellation on drop are unchanged. The underlying fixed 8192-entry correlation ring and 32-probe admission bound remain unchanged; saturation returns the existing typed slot-admission error. Deferred raw asks retain their 30-second default, and actor deferred asks retain their supplied absolute timeout. No additional queue, task, wrapper allocation or lifetime-expiry authority is introduced. `DeferredAsk::wait` now returns the native `AlignedBytes`; `wait_aligned` remains an equivalent spelling. Call `wait_bytes` only when explicitly choosing shared Bytes metadata promotion. Deferred throughput fixtures use the native result type and require a fresh matching release baseline.

`AskForwarder::new_with_limits` configures aggregate request/fallback retained bytes and an operational lifetime. Defaults are 64 MiB and five minutes. Every task, including a no-application-timeout task, expires by its operational lease. This cancels only the ask, never the healthy destination transport. All request/fallback owners are charged by full capacity before enqueue; failure, cancellation, panic, and shutdown release byte/count permits. Destination replies remain subject to their independently bounded receive-owner pools and the same operational expiry.

Workers are clamped to 1..=64, queued global admission to 128..=65536 plus 16 outstanding slots, and the byte budget to 1..=u32::MAX. Queued work is earliest-deadline-first with admission-order ties. The fixed-width Patricia deadline index visits at most 128 key bits per operation, independent of queue length. Its tree/task/free-list storage is allocated once per worker; equal-deadline tasks share an intrusive FIFO. Each worker owns 16 fixed pinned future slots and cached wakers, with readiness tracked by a bitmap instead of per-operation FuturesUnordered nodes. A stale wake may poll a reused slot but cannot recover an old future or outcome.

A single atomic publisher-close state replaces the forwarding admission mutex. Shutdown closes new publishers and waits for already admitted publishers to finish enqueue or rejection before workers close their receivers. A contended one-shot publication reservation returns `WriteQueueFull`; closed publication returns `Shutdown`. This does not block or spin. Request and terminal-fallback payloads move rather than clone during forwarding. Preallocated `ArrayQueue` rings replace Tokio channel nodes, and borrowed count/byte guards replace per-job owned semaphore references. Per-worker queued deadline storage is bounded by its ring capacity plus 16; the aggregate count budget prevents exceeding that backing storage. Receiver cancellation and in-progress publisher rollback return ownership before terminal reconciliation. See [forwarding admission and reclamation](FORWARDER_ADMISSION.md) for exact metadata budgets, scoped counter tests, and remaining whole-path performance evidence limits.


## Required host verification

Run the unchanged complete validation matrix. New regressions cover aligned count/byte exhaustion and sliced-owner release; byte-fill overflow, bounded checkout and recovery; global serializer exhaustion; writer exact-boundary/pointer stability, aligned scratch saturation/pop reuse, oversized archive rejection and same-context recovery; forward owner provenance, full-capacity charging, fallback/queue admission, operational expiry and cleanup. Existing initialized receive, zero-length alignment, typed prefix parity and forwarder shutdown/race tests remain in the matrix. No builds, tests, formatter, compiler, dependency installation or network access were run while authoring this patch.

Generic `HeaderPooled` writes now retain a native pooled chunk beside byte header/prefix chunks. Preparation, append, scatter writes and parked partial writes preserve that exact owner and its advanced view. Pending storage charges the full pooled capacity until the batch is released, including an empty remaining view, rather than subtracting the wire cursor. No `Bytes::from_owner` promotion is needed. Receipt-merge failures reject the batch instead of silently selecting opaque decoding. A three-chunk inline backing removes the per-frame batch-vector allocation as well. Larger mixed batches retain vector-backed storage; complete-path cost acceptance still requires host execution.

Owned immediate responses likewise move `ForwardPayload` directly into the native pooled response slot. Preallocated response-batch admission and parking add no shared-owner wrapper, preserving the full capacity charge through partial writes and releasing it only when the parked frames are recycled.
